# Astro 구현 최종 검토

독립 검토 범위는 `7f23d7f..1b742ed`입니다. 승인된 설계·계획, 실제 코드와 격리된 입력 재현을 검토한 결과 Critical 0건, Important 1건, Minor 2건을 받았습니다. 검토 후 Important 1건을 회귀 테스트로 수정했습니다.

## 수정한 중요 문제

표준 Markdown의 `![화면](images/screen%20shot.png)`처럼 공백이나 한글을 인코딩한 이미지 경로가 유효한 파일인데도 거부되어 개발 페이지와 운영 빌드가 실패했습니다.

로컬 파일명 인코딩을 한 번 해석한 뒤 경로와 realpath를 검증하도록 수정했습니다. 인코딩으로 새 `/`·`\` 구분자를 만드는 입력, traversal, 제어 문자, 잘못된 인코딩과 외부 symlink는 계속 거부합니다. 이미 해석한 `%20` 같은 파일명 문자열을 다시 해석하지 않습니다. 외부 HTTPS 이미지 정책은 유지합니다.

수정 전 한글·공백 이미지 렌더링 테스트가 `Invalid image path`로 실패하는 것을 확인했고, 수정 후 이미지 경계 테스트 10개가 통과했습니다. 브라우저 fixture도 공백이 있는 파일을 `%20` Markdown URL로 참조하도록 변경했습니다.

## 검증 중 수정한 테스트 서버 경합

기존 fixture의 종료 제한 타이머가 변경 가능한 `child` 변수를 참조해, 이전 서버가 끝난 뒤 시작한 새 서버에 SIGKILL을 보낼 수 있었습니다. 실제 브라우저 검증의 재시작 실패를 조사하고 새 서버가 SIGKILL을 받는 회귀 테스트로 재현했습니다. 종료할 프로세스를 고정하고 종료 후 타이머를 취소하며 signal로 종료된 상태도 확인하도록 수정했습니다. 재현 테스트와 실제 서버 재시작이 모두 통과했습니다.

## 최종 검증

- 단위·HTML validator·fixture 수명 주기: 15개 파일의 108개 테스트 통과
- 브라우저: 실제 콘텐츠/반응형/Mermaid 23개 + 격리된 상호작용·런타임·보안·자동 갱신 14개 통과, skip 0개
- Astro·TypeScript·Vue·Svelte 검사: 오류·경고 0개
- lint·format·peer 검사 및 전체 의존성 low 이상 감사 통과, 알려진 취약점 0개
- 기본 프로덕션 빌드와 30개 정적 HTML의 경로·공개 정책·canonical·이미지·HTML 중첩 검증 통과

## 경미한 후속 항목

1. `src/lib/markdown/render.ts`: 본문 내부 링크에 query 또는 fragment가 있으면 프레임워크 접두사 변환에서 빠집니다. 예를 들어 Vue 글의 `/ko/posts/foo/#section` 링크를 누르면 React 별칭으로 이동합니다. 일반 링크와 헤더의 프레임워크·언어 전환은 검증됐습니다.
2. `src/lib/markdown/images.ts`: 첫 이미지가 reference 형식이고 뒤에 inline 이미지가 있으면 본문 순서는 맞지만 기본 썸네일은 뒤의 inline 이미지가 됩니다. 명시한 `thumbnail`은 우선합니다. 정의를 먼저 수집한 뒤 이미지 출현 순서로 URL을 등록하는 후속 수정이 필요합니다.

두 항목은 독립 검토의 Minor 분류를 유지해 이번 중요 수정과 구분해 기록했습니다.

## 검토 초점별 결과

| 항목 | 확인 결과 |
| --- | --- |
| YAML 날짜·timezone·null·누락 | ISO 데이터와 공통 표시값으로 UI별 재해석을 방지합니다. `updatedAt`의 null·누락을 유지합니다. `createdAt: null`의 epoch 변환은 이전 스키마와 같으며 새 회귀는 아닙니다. |
| 한글·공백·밑줄·중첩·percent encoding | 글 경로와 충돌 진단을 확인했습니다. 발견한 이미지 인코딩 문제는 위 회귀 테스트로 수정했습니다. |
| 없는 번역의 locale/framework 전환 | 헤더 링크는 나머지 URL 축을 보존하고 없는 번역 상세는 404입니다. 본문 query/fragment 링크의 예외는 Minor로 남았습니다. |
| 외부 파일 삭제·동일 경로 이미지 교체 | store 교체·digest 변경·빌드 staging 정리와 열린 브라우저 자동 갱신·재시작 검증을 확인했습니다. |
| 스크립트·이벤트·MDX·서버 경로·이미지 마커 | 비실행 Markdown, raw HTML 제거, 최종 HTML 정화, 세 삽입 지점과 props 경계를 검토했습니다. 추가적인 실행·서버 경로 유출 문제는 확인되지 않았습니다. |

검토자가 판단을 유보한 범위도 확인했습니다. 배포·Netlify·Build Hook·원격 checkout은 사용자가 마지막 수동 단계로 유보했으므로 변경하지 않습니다. 브라우저·빌드 실행 증거는 구현자가 직접 확인했으며 검토자가 재실행한 결과와 구별합니다. 이번 코드 검토를 별도의 전수 보안 감사로 표현하지 않습니다.

## 구현 중 판단한 사항과 비용

다음은 구현 ledger의 모든 `Ruling:`에 대응하는 기록입니다.

1. 기존 고립 cloud checkout에서 직접 실행했습니다. 추가 worktree를 만들지 말라는 환경 지침과 사용자 승인에 따릅니다. 비용: 추가 checkout 격리는 없습니다.
2. 노출되지 않은 스킬 보조 스크립트 대신 task brief·기준 커밋·RED/GREEN·ledger를 수동 관리했습니다. 비용: 보조 도구에 의한 자동 기록 검증이 없습니다.
3. release-age 정책 때문에 Astro 7.4.1 대신 같은 7 계열의 성숙한 7.4.0을 설치했습니다. 비용: 새 패치 도입을 미뤘습니다.
4. 기존 미발행 글에 title이 없어 파일명에서 제목을 유도했습니다. 기존 생성기와 같은 작성 계약입니다. 비용: 의도하지 않은 title 누락도 파일명으로 표시됩니다. 명시한 잘못된 제목은 계속 실패합니다.
5. 같은 release-age 사유로 Vue integration 7.1.0, Astro checker 0.9.10을 선택했습니다. 비용: 새 패치 도입을 미뤘습니다. 호환되는 TypeScript 6.0.3을 사용합니다.
6. 프레임워크마다 하나의 `BlogPage`에 전체 UI를 응집시켰습니다. 데이터·CSS만 공유하며 UI는 독립적입니다. 비용: 개별 컴포넌트 파일이 커져 추후 분리가 필요할 수 있습니다.
7. HTML validator가 Astro의 본문 island 스타일을 flow 요소로 인정하도록 했습니다. paragraph/figure 중첩과 닫힘 검사는 유지합니다. 비용: body의 style 위치 자체는 지적하지 않습니다.
8. 재현 가능한 소개 문서 fixture용 `BLOG_ABOUT_DIR`을 추가했습니다. 기본 HTTPS README fetch는 유지합니다. 비용: 선택 환경 설정 하나가 늘었습니다.
9. 복사·목차·이미지 오류·런타임 분리 검증은 실제 vault에 의존하지 않는 Task 7 fixture로 모았습니다. 비용: Task 5·6 시점의 해당 검증은 미뤘으며 최종 실행에서 완료했습니다.
10. 공식 Content Layer watcher/store의 자동 갱신을 사용하고 중복 HMR 전송을 추가하지 않았습니다. 비용: upstream 동작이 바뀌면 회귀 테스트를 기준으로 Environment API 갱신 처리를 보완해야 합니다.
11. 독립 프로세스용 `BLOG_CACHE_DIR`·`BLOG_OUT_DIR`을 추가했습니다. Astro의 rename 제약 때문에 fixture 출력은 같은 파일시스템에 둡니다. 비용: 테스트용 설정 표면이 늘었습니다.
12. 제거한 Babel/React Compiler의 선택 peer가 남는 문제를 해소하려고 정리된 manifest에서 lockfile을 다시 계산했습니다. 공급망 정책은 유지했습니다. 비용: 호환 범위의 전이 의존성이 바뀌어 전체 재검증이 필요했습니다.
13. 단위 runner의 기존 dist 의존을 없애고 산출물 검증을 `verify:build`와 새 빌드 fixture로 옮겼습니다. 비용: 산출물 검증은 별도의 필수 명령으로 실행해야 합니다.
14. 의존성 감사의 advisory 3건을 해소하도록 Tinypool을 패치 범위로 제한하고 KaTeX 0.18.2를 고정했습니다. 잘못된 breaking release로 deprecated된 0.18.11은 피했습니다. 비용: Mermaid와의 호환성을 재검증해야 했으며 수식 레이블을 포함한 브라우저 fixture로 확인했습니다. 감사 기준은 낮추지 않았습니다.

15. 배포 준비 검토는 사용자가 마지막 단계로 유보한 범위여서 수행하지 않았습니다. 비용: 현재 운영 배포 준비 완료를 주장하지 않습니다.
16. 독립 검토자가 브라우저·빌드를 중복 실행하지 않고 구현자가 수정 후 직접 실행했습니다. 비용: 런타임 증거는 별도 검토자의 재실행 결과가 아닙니다.
17. 이번 코드 검토를 전수 보안 감사로 확대하지 않았습니다. 비용: 검토 범위를 넘어선 보안 보증은 제공하지 않습니다.
18. 구현 요청의 범위에 맞춰 feature 브랜치와 checkout을 보존합니다. 비용: push·merge·게시 여부는 사용자의 이후 결정으로 남습니다.

## 전달 상태

구현과 수정은 feature 브랜치에 보존합니다. push·merge·배포와 cloud snapshot 게시를 실행하지 않습니다. 클라우드 설치·시작 지침은 실제 실행 후 설정 초안에 저장했습니다. 새 task로 복원한 환경 검증은 아직 수행하지 않았습니다. `blog-content`의 추적 파일과 `netlify.toml`은 변경하지 않았습니다.
